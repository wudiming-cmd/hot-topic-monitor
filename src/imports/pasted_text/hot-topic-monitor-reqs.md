# 多平台热点监测工具 — 需求说明书

> 版本 v1.0 ｜ 用途:交付给开发同学实现 ｜ 类型:团队内部运营分析工具(非 C 端产品)

---

## 1. 项目背景与目标

做一个**内部用的多平台热点监测工具**,持续采集各平台"什么在火",并产出排序榜单,辅助运营团队做选题判断。

核心要回答三个问题:

1. 各平台现在有哪些**热点内容 / 热点话题 / 热点新闻 / 热点娱乐**?
2. 现在有哪些**热门梗图(meme)**?
3. **哪个最受欢迎、涨得最快**(跨平台综合排序)?

工具产出的是"情报/选题信号",不直接面向终端用户。

---

## 2. 范围与合规边界(必读,影响实现方式)

### 2.1 范围内
- 采集**公开的热点信号与元数据**:标题、链接、作者、发布时间、热度指标(播放/点赞/评论/转发/收藏/upvote 等)、搜索趋势。
- 基于上述信号做**热度计算、上升速度计算、跨平台综合排序、去重、变化追踪**。
- **梗图发现**:通过官方授权的梗图/GIF API(Giphy / Tenor / Imgflip)获取 trending 内容(这些 API 本身允许调用与嵌入)。
- **广告情报**:通过 Meta 广告资料库(Ad Library)查询某品类正在投放的广告。

### 2.2 范围外 / 红线
- **不批量下载、存储、再分发受版权保护的内容**(如卡通角色图、他人原创插画/梗图素材等)。需要展示媒体时,只使用官方 API 允许的方式(如缩略图、官方提供的嵌入/预览,或 Giphy/Tenor 这类授权调用)。
- 各平台**服务条款(ToS)和 robots 规则**必须遵守;速率限制要做退避处理。
- 关于"点击率 / 受众率":**他人内容的真实点击率是私有数据,无法获取**。本工具用公开信号(绝对热度 + 上升速度 + 互动率)作为"受欢迎程度"的代理指标(见 §3)。

---

## 3. 核心指标定义

| 指标 | 含义 | 计算方式 |
|---|---|---|
| 绝对热度 popularity | 内容的累计热度 | 各平台原始指标(播放/赞/评论/upvote 等),归一化到 0–1 |
| 上升速度 velocity | 单位时间的热度增量 | (本次热度 − 上次采集热度) / 时间间隔;用于抓"正在上升"的内容 |
| 互动率 engagement_rate | 单位曝光的互动 | (赞+评论+转发) / 曝光或播放量 |
| 综合热度分 composite_score | 跨平台可比的总分 | 三项各自归一化后加权求和(velocity 权重建议最高),再跨平台对同一话题/梗去重合并 |

> 权重可配置;默认建议 velocity:popularity:engagement = 0.5 : 0.3 : 0.2,后续按效果调。

---

## 4. 功能需求

### 4.1 多渠道采集(适配器架构)
- 每个数据源实现为一个独立 **Adapter**,遵循统一接口 `fetch(limit) -> List[TrendItem]`。
- 加新平台 = 新增一个 Adapter,**主流程不改动**。
- 单个源失败不影响其它源(异常隔离 + 日志告警)。

### 4.2 数据归一化
- 所有 Adapter 输出统一结构 `TrendItem`(见 §6)。

### 4.3 去重
- 同一话题/梗常被多平台、多次收录,需按 URL + 归一化标题(可加图像感知哈希 pHash 辅助)去重合并,合并时保留多平台来源信息。

### 4.4 热度计算与排序
- 按 §3 计算 composite_score,输出总榜 + 分平台榜 + 分类榜(新闻/社交/娱乐/科技/梗图)。

### 4.5 热点变化追踪
- 每次采集与历史对比,标记:**新冒出**(首次出现)、**持续在榜**、**快速上升**、**已回落**。
- 这是"选题信号"的关键,比单次快照有用得多。

### 4.6 梗图发现
- 通过 Giphy / Tenor / Imgflip 拉取 trending 梗图/模板;Reddit 梗图子版块(r/memes、r/dankmemes)取 hot;Know Your Meme 看梗的背景与热度。
- 只保存元数据与官方允许的预览/嵌入信息。

### 4.7 广告情报
- 调用 Meta 广告资料库,按关键词/品类/地区查询**正在投放**的广告,作为"已被市场验证"的信号。

### 4.8 (可选,P3)以图搜图 / 关键词搜索
- 上传一张图 → 在**合规素材库(正版图库 API / CC / 公共领域 / 自有素材)**或自建索引中找相似(pHash 近重复 + CLIP 视觉 embedding + 向量库)。
- 关键词 → 对素材建索引(标签 / OCR / 图文 embedding)做语义检索。
- 注意:此模块的检索对象必须是合规来源,不用于检索/获取受版权保护的他方内容。

### 4.9 存储
- 结构化数据入库(热点条目、历史快照、来源映射);媒体仅存合规来源的内容或预览。

### 4.10 调度
- 定时采集(可配置频率,如每小时/每 30 分钟),支持手动触发。

### 4.11 输出 / 展示
- MVP:导出 JSON / CSV + 命令行预览。
- 进阶:Web 看板(总榜、趋势变化、按平台/分类筛选)。

## 5. 数据源与 API 清单 ★

> 优先级:**A** = 官方 API 好用且免费,优先做；**B** = 官方 API 受限或较贵；**C** = 官方不开放公开数据,需第三方或暂缓。

| 来源 | 用途 | 接口 / 方法 | 密钥 | 费用 | 限制与注意 | 优先级 |
|---|---|---|---|---|---|---|
| **Google News** | 热点新闻 | RSS:`news.google.com/rss?hl=&gl=&ceid=` | 否 | 免费 | 用 hl/gl/ceid 控制语言地区;依赖 feedparser | A |
| **Hacker News** | 科技热门 | Firebase 官方 API(topstories + item) | 否 | 免费 | 需逐条取 item,控制并发 | A |
| **Reddit** | 社交热门 / 梗图 | OAuth API:`/r/{sub}/hot`;轻量可用公开 `.json`(须带 User-Agent) | OAuth(生产) | 免费层非商业;商业 ~$0.24/1000 次且需合同 | 免费层限速严;高频/商用需注册 App 走官方授权 | A |
| **Google Trends** | 搜索趋势 / rising | pytrends(**非官方**库) | 否 | 免费 | 非官方接口,可能不稳定/被限流,做好降级 | A |
| **YouTube** | 热门视频 + 统计 | Data API v3:`videos?chart=mostPopular&part=snippet,statistics&regionCode=` | 是(免费) | 免费配额 | 默认每日 10,000 配额单位,注意单次调用消耗 | A |
| **TMDb** | 热点娱乐(影视) | `/3/trending/all/{day|week}` | 是(免费) | 免费 | 申请免费 key 即可 | A |
| **Giphy** | trending 梗图/GIF | 官方 API trending endpoint | 是 | 免费(有速率限制) | 官方允许调用与嵌入;遵守其使用条款 | A |
| **Tenor** | trending GIF | 官方 API(Google)trending | 是 | 免费 | 同上 | A |
| **Imgflip** | trending 梗图模板 | `get_memes` | 否/账号 | 免费 | 拿热门模板,适合看"什么梗格式在火" | A |
| **Meta 广告资料库** | 在投广告情报 | Ad Library API(按关键词/地区查询) | 需访问令牌 | 免费 | 需 Meta 开发者访问权限;也可经已连接的 Meta Ads connector 调用 | B |
| **X (Twitter)** | 帖子 + 互动数 | API v2(搜索/趋势) | 是 | **按量付费**:约 $0.005/条读取,无免费层,每月上限 200 万条读取 | 读取密集会很贵,需做配额控制;只在必要时用 | B |
| **Pinterest** | 视觉趋势 | 官方 API(OAuth,含 trends 接口) | OAuth | 免费层有限 | 读取约 1000 req/min;大范围公开数据偏第三方(灰色) | B |
| **TikTok** | 短视频热点 | **官方无公开数据 API**(Display=自有授权内容;Research=仅学术机构) | — | — | 想要公开热点数据须走第三方数据商(如 Tikapi 等),注意条款 | C |
| **Know Your Meme** | 梗背景/热度 | 无官方 API(RSS/页面) | 否 | — | 注意站点 ToS 与抓取频率 | C |

## 6. 统一数据结构(TrendItem)

```python
TrendItem:
    source: str            # 来源平台,如 "youtube"
    category: str          # news / social / entertainment / tech / meme
    title: str
    url: str
    media_url: str | None  # 仅合规来源的图/封面/预览
    popularity: float | None      # 归一化后的绝对热度
    velocity: float | None        # 上升速度
    engagement_rate: float | None
    composite_score: float | None # 综合排序分
    author: str | None
    published_at: str | None      # ISO 时间
    fetched_at: str               # 本次采集时间(算 velocity 用)
    sources: list                 # 去重合并后,该话题在哪些平台出现
    extra: dict                   # 各平台特有字段(评论数、upvote ratio 等)
```

## 7. 技术要求 / 架构建议

- **语言/栈**:不限,建议 Python(生态成熟);存储建议 PostgreSQL(或 MVP 用 SQLite),媒体用对象存储。
- **架构**:Adapter 模式 + 统一 Schema + 归一化/去重/打分流水线 + 调度器 + 输出层。
- **容错**:单源失败隔离、超时控制、速率限制 + 指数退避(带 jitter)。
- **可配置**:目标地区/语言、采集频率、关键词、权重,均走配置文件或环境变量,不写死。
- **历史快照**:保存每次采集结果,供 velocity 与变化追踪计算。
- **密钥管理**:所有 API key 走环境变量 / secret 管理,不进代码库。

---

## 8. 非功能需求
- **可扩展**:新增平台只需加 Adapter。
- **合规**:遵守各平台 ToS、robots、速率;媒体处理遵守 §2 红线。
- **可观测**:每个源的采集状态、成功条数、失败原因有日志。
- **幂等**:重复运行不产生脏数据(靠去重键)。

## 10. 建议里程碑

| 阶段 | 内容 |
|---|---|
| **P0(MVP)** | A 档免费源(Google News / HN / Reddit / Google Trends / YouTube / TMDb)+ 归一化去重 + composite_score 排序 + 入库 + JSON/CSV 导出 |
| **P1** | 梗图源(Giphy / Tenor / Imgflip / Reddit 梗图子版)+ 热点变化追踪 + 定时调度 |

## 11. 验收标准
- 能稳定定时采集 A 档全部数据源,单源故障不影响整体。
- 输出的总榜能正确按 composite_score 排序,且同一话题/梗跨平台已去重合并。
- 能区分"新冒出 / 持续 / 上升 / 回落"四种状态。
- 梗图模块能返回当下 trending 的梗(经官方 API)。
- 所有数据源遵守其速率限制与使用条款;媒体处理符合 §2 范围约束。
